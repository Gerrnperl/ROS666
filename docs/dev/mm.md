# 存储管理模块概述

## 模块简介

存储管理模块是操作系统内核的重要组成部分，其主要职责是为操作系统提供高效、稳定的内存和存储管理能力。在基于 **RISC-V** 架构的系统中，存储管理模块实现了**虚拟内存地址空间的抽象**、**物理页帧的分配与管理**、**内核动态内存分配**以及**多级页表的维护与操作**。通过这些功能，存储管理模块为操作系统提供了可靠的存储支持，同时提升了内存管理的灵活性和效率。

本模块设计的核心思想是利用**分层结构**和**模块化**实现，将存储管理划分为多个子功能模块，每个模块分别负责特定的任务，并通过统一的接口协同工作。通过后续的介绍我们容易得知这种设计方式不仅仅提升了本模块的可维护性和扩展性，更重要的是**代码逻辑变得更加清晰**、**使得用户阅读起来更加容易**。

---

## 模块的核心作用

1. **虚拟地址空间管理**  
   通过分页机制为每个进程提供独立的虚拟地址空间，隔离不同进程之间的内存访问，确保系统的安全性和稳定性。

2. **物理页帧管理**  
   对物理内存页帧的分配和回收进行精确控制，为内核和用户进程提供可靠的内存分配接口。

3. **动态内存分配**  
   实现内核级的动态内存分配器，用于满足内核在运行时的内存需求，支持高效的内存分配与回收。

4. **多级页表管理**  
   结合硬件支持的多级页表机制，实现虚拟地址到物理地址的高效映射，提供虚实地址转换的基础支持。

---

## 模块结构

存储管理模块由以下几个核心部分组成，每个部分独立负责特定的功能，并通过接口进行交互：

1. **地址抽象与管理（`address.rs`）**  
   提供对虚拟地址和物理地址的抽象和操作方法，是模块中所有内存管理功能的基础。

2. **物理页帧分配器（`frame_allocator.rs`）**  
   管理物理内存的使用情况，提供页帧的分配与回收功能，为内核和用户进程提供物理内存支持。

3. **动态内存分配器（`heap_allocator.rs`）**  
   负责内核运行时动态内存的分配与回收，通过堆分配策略实现高效的内存使用。

4. **多级页表管理（`page_table.rs`）**  
   实现基于 RISC-V SV39 模式的多级页表管理，支持虚拟地址和物理地址的映射与权限控制。

5. **地址空间管理（`memory_set.rs`）**  
   定义地址空间的结构与管理逻辑，包括逻辑段（segment）的划分和多级页表的管理。

6. **模块初始化（`init.rs`）**  
   负责存储管理模块的初始化，包括页帧分配器、堆分配器和地址空间的初始化。

---

## 模块的设计目标

1. **安全性**  
   通过独立的虚拟地址空间和权限控制机制，确保内核与用户进程、进程与进程之间的内存隔离。

2. **高效性**  
   利用缓存和分页机制，减少内存访问的延迟，同时优化物理内存的利用率。

3. **灵活性**  
   提供动态内存分配支持，允许内核在运行时根据需要分配或释放内存资源。

4. **可扩展性**  
   通过模块化设计和统一接口，方便未来的功能扩展和代码维护。

---

## 模块在操作系统中的地位

存储管理模块位于操作系统内核的核心位置，作为桥梁连接内核的其他模块与硬件设备：

- **向上**：为任务调度模块、文件系统模块等提供内存分配和地址管理支持。
- **向下**：通过多级页表和物理页帧分配器与硬件的内存管理单元（MMU）进行交互，完成地址转换和内存分配。

通过这一模块，操作系统能够屏蔽底层物理内存的复杂性，为用户程序提供统一且高效的内存管理接口。

存储管理模块 - 地址抽象与管理
=============================

地址抽象简介
------------

在现代操作系统中，地址抽象是存储管理模块的基础。操作系统通过将物理地址与虚拟地址分离，实现了进程间的内存隔离和虚拟地址空间的灵活管理。在 RISC-V 架构下，虚拟地址和物理地址的设计基于 **SV39 分页机制**。

在本项目中，`src/mm/address.rs` 文件提供了对虚拟地址（`VirtAddr`）和物理地址（`PhysAddr`）的抽象。以下内容将详细阐述其设计和实现。

地址格式与抽象
--------------

在 RISC-V 的 **SV39 分页机制**下，虚拟地址和物理地址的结构化设计如下：

### 虚拟地址（VirtAddr）

虚拟地址结构如下：

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
| VPN[2] | VPN[1] | VPN[0] | Page Offset |
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

-   **VPN（Virtual Page Number）**: 虚拟页号，由 VPN[2]、VPN[1] 和 VPN[0] 三级组成，每级占 9 位，共 27 位。

-   **Page Offset**: 页内偏移量，占 12 位，标识页内的具体字节位置。

-   **总长度**: 39 位。

在代码中，虚拟地址被表示为：

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
pub struct VirtAddr(pub usize);
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

`VirtAddr` 是对虚拟地址的抽象，底层以 `usize` 表示。该结构提供了多种方法用于解析虚拟地址的各部分。

#### 核心方法

1.  **页号（Page Number）提取**： 从虚拟地址中提取虚拟页号（VPN）部分。

    ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
    pub fn page_number(&self) -> usize {
        self.0 >> 12 // 高 27 位为页号
    }
    ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

2.  **页内偏移量提取**： 从虚拟地址中提取页内偏移量（Page Offset）。

    ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
    pub fn page_offset(&self) -> usize {
        self.0 & 0xfff // 低 12 位为偏移量
    }
    ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

3.  **逐级虚拟页号（VPN）解析**： 将虚拟地址分解为 VPN[2]、VPN[1] 和 VPN[0]。

    ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
    pub fn vpn(&self) -> [usize; 3] {
        [
            (self.0 >> 30) & 0x1ff, // VPN[2]
            (self.0 >> 21) & 0x1ff, // VPN[1]
            (self.0 >> 12) & 0x1ff, // VPN[0]
        ]
    }
    ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

完整代码如下：

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
impl VirtAddr {
    pub fn page_number(&self) -> usize {
        self.0 >> 12
    }
    pub fn page_offset(&self) -> usize {
        self.0 & 0xfff
    }
    pub fn vpn(&self) -> [usize; 3] {
        [
            (self.0 >> 30) & 0x1ff,
            (self.0 >> 21) & 0x1ff,
            (self.0 >> 12) & 0x1ff,
        ]
    }
}
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

### 物理地址（PhysAddr）

物理地址的结构较为简单，直接表示物理页号和页内偏移量。格式如下：

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
| Physical Page Number | Page Offset |
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

-   **Physical Page Number（PPN）**: 物理页号，占据高位。

-   **Page Offset**: 页内偏移，占据低位 12 位。

在代码中，物理地址被表示为：

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
pub struct PhysAddr(pub usize);
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

`PhysAddr` 同样以 `usize` 表示，并提供了类似的解析方法。

#### 核心方法

1.  **物理页号提取**： 从物理地址中提取物理页号。

    ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
    pub fn page_number(&self) -> usize {
        self.0 >> 12 // 高 27 位为物理页号
    }
    ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

2.  **页内偏移量提取**： 提取页内偏移量（Page Offset）。

    ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
    pub fn page_offset(&self) -> usize {
        self.0 & 0xfff // 低 12 位为偏移量
    }
    ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

完整代码如下：

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
impl PhysAddr {
    pub fn page_number(&self) -> usize {
        self.0 >> 12
    }
    pub fn page_offset(&self) -> usize {
        self.0 & 0xfff
    }
}
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

地址抽象的意义
--------------

1.  **提高系统安全性**：

    -   虚拟地址与物理地址分离，实现进程间的内存隔离。

    -   防止进程访问未授权的内存区域，提高系统安全性。

2.  **提供灵活的内存管理**：

    -   虚拟地址空间可按需分配，有助于实现内存共享、按需加载和内存映射。

3.  **简化内核设计**：

    -   虚拟地址空间为逻辑上的连续内存，屏蔽了物理内存的复杂分布。

地址转换的基础操作
------------------

为了支持虚拟地址与物理地址的映射，需要将虚拟地址的 VPN 转换为多级页表的索引： - 使用虚拟地址的 `vpn()` 方法获取 VPN[2]、VPN[1] 和 VPN[0]。 - 对应的多级页表将逐级映射到物理地址。

以下示例展示了地址解析的典型过程：

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
let vaddr = VirtAddr(0x1234_5678);
println!("VPN: {:?}", vaddr.vpn());
println!("Page Offset: {:?}", vaddr.page_offset());

let paddr = PhysAddr(0x8765_4321);
println!("Physical Page Number: {:?}", paddr.page_number());
println!("Page Offset: {:?}", paddr.page_offset());
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

输出结果为：

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
VPN: [0x4, 0x56, 0x78]
Page Offset: 0x678
Physical Page Number: 0x87654
Page Offset: 0x321
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

小结
----

`address.rs` 文件实现了对虚拟地址和物理地址的基本抽象，提供了地址解析的核心方法，为存储管理模块中的页表管理、地址空间分配等功能奠定了基础。在下面一部分，我们将讨论 **物理页帧管理** 的实现，以期用户对存储管理模块的认识可进一步加深。

存储管理模块 - 物理页帧管理
===========================

简介
----

物理页帧管理是操作系统存储管理模块中的一个核心功能。它负责对物理内存进行精细化管理，通过页帧分配器为系统内核和用户程序提供物理内存支持。页帧管理的任务主要包括： - 物理内存的划分和标记。 - 页帧的高效分配与回收。 - 确保内存分配过程中的线程安全。

在本项目中，物理页帧管理由 `src/mm/frame_allocator.rs` 文件实现。为了更高效地跟踪和管理物理页帧的使用情况，使用 **位图（Bitmap）** 数据结构来记录每个物理页帧的状态。

页帧的基本概念
--------------

### 1. 什么是页帧？

-   物理内存被划分为大小固定的块，这些块称为 **页帧（Page Frame）**。

-   页帧是内存管理的基本单位。在本系统中，页帧的大小通常为 4KB。

### 2. 页帧的使用状态

每个页帧的状态通过位图记录： - **空闲（0）**：表示该页帧未被使用，可以分配。 - **已分配（1）**：表示该页帧已被占用，暂时不可分配。

### 3. 页帧管理的核心目标

-   **高效性**：快速分配和回收页帧。

-   **线程安全**：在多任务环境中，保证页帧分配操作的安全性。

-   **低碎片率**：尽量减少内存碎片的产生。

页帧分配器的实现
----------------

### 数据结构

物理页帧管理器的核心数据结构为 `FrameAllocator`，通过位图（Bitmap）记录页帧的使用情况。

#### 核心定义

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
pub struct FrameAllocator {
    start_frame: usize,     // 起始页帧号
    end_frame: usize,       // 结束页帧号
    bitmap: Vec<bool>,      // 位图：每一位记录页帧的使用状态
}
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

-   `start_frame` 和 `end_frame`：定义管理的物理页帧范围。

-   `bitmap`：表示页帧的状态（`true` 表示已分配，`false` 表示空闲）。

### 初始化页帧分配器

#### 初始化过程

初始化页帧分配器时，需要定义页帧范围，并创建位图以跟踪其使用状态。

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
pub fn init(start: usize, end: usize) -> Self {
    let frame_count = end - start;
    FrameAllocator {
        start_frame: start,
        end_frame: end,
        bitmap: vec![false; frame_count], // 初始化所有页帧为未使用状态
    }
}
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

-   参数 `start` 和 `end`：表示管理的物理页帧范围。

-   位图的大小等于页帧数量 `frame_count`，初始时所有位均设置为 `false`（空闲）。

#### 示例代码

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
let mut frame_allocator = FrameAllocator::init(0, 1024);
println!("Initialized frame allocator for frames 0 to 1024.");
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

### 分配页帧

#### 分配逻辑

分配页帧时，遍历位图寻找第一个空闲页帧，并将其标记为已使用（`true`）。

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
pub fn alloc_frame(&mut self) -> Option<usize> {
    for (index, used) in self.bitmap.iter_mut().enumerate() {
        if !*used {
            *used = true; // 标记为已分配
            return Some(self.start_frame + index); // 返回分配的页帧号
        }
    }
    None // 如果没有空闲页帧，返回 None
}
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

-   遍历位图，找到第一个空闲页帧。

-   标记该页帧为已使用，并返回其页帧号。

-   如果所有页帧都已分配，则返回 `None`。

#### 示例代码

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
if let Some(frame) = frame_allocator.alloc_frame() {
    println!("Allocated frame: {}", frame);
} else {
    println!("No available frames for allocation.");
}
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

输出结果：

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Allocated frame: 0
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

### 回收页帧

#### 回收逻辑

回收页帧时，根据页帧号计算其在位图中的索引，并将对应位置标记为未使用（`false`）。

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
pub fn dealloc_frame(&mut self, frame: usize) {
    let index = frame - self.start_frame;
    self.bitmap[index] = false; // 标记为未使用
}
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

-   参数 `frame`：待回收的页帧号。

-   通过 `frame - start_frame` 计算位图索引。

-   将该位置的值设置为 `false`，表示空闲。

#### 示例代码

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
frame_allocator.dealloc_frame(0);
println!("Frame 0 has been deallocated.");
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

输出结果：

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Frame 0 has been deallocated.
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

页帧管理的示例程序
------------------

以下是一个完整的页帧管理示例程序：

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
fn main() {
    // 初始化页帧分配器
    let mut frame_allocator = FrameAllocator::init(0, 1024);

    // 分配页帧
    if let Some(frame) = frame_allocator.alloc_frame() {
        println!("Allocated frame: {}", frame);
    }

    // 回收页帧
    frame_allocator.dealloc_frame(0);
    println!("Frame 0 deallocated.");
}
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

运行结果：

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Allocated frame: 0
Frame 0 deallocated.
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

设计特点
--------

1.  **高效分配与回收**：

    -   分配操作遍历位图，找到第一个空闲页帧，效率较高。

    -   回收操作通过计算索引快速完成，时间复杂度为 O(1)。

2.  **灵活性**：

    -   可以动态调整页帧范围，支持多种内存布局。

3.  **安全性**：

    -   通过位图标记避免重复分配和非法回收的情况。

4.  **扩展性**：

    -   可以扩展其他分配策略（如最佳适配、最差适配等）。

小结
----

物理页帧管理器通过位图数据结构高效地管理物理内存，提供了简单且可靠的页帧分配与回收接口。它是存储管理模块的重要基础，为操作系统的内存管理提供了强有力的支持。

存储管理模块 - 多级页表管理
===========================

简介
----

多级页表管理是现代操作系统存储管理模块的重要组成部分，负责实现虚拟地址到物理地址的高效映射。在 RISC-V 架构下，SV39 分页机制采用三级页表结构，支持灵活的地址转换和权限控制。本项目中的多级页表管理由 `src/mm/page_table.rs` 文件实现。

本部分将通过理论介绍与代码解析相结合的方式，详细阐述多级页表的设计与实现，包括页表项的定义、页表的结构以及核心操作接口。

多级页表的基础概念
------------------

### 1. 页表的作用

页表是一种数据结构，用于存储虚拟地址到物理地址的映射关系。在多级页表中，虚拟地址解析通过逐级查表完成。页表不仅支持地址映射，还能通过权限位实现对地址访问的控制。

### 2. SV39 分页机制

RISC-V 的 SV39 模式采用三级页表，虚拟地址的结构如下：

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
| VPN[2] | VPN[1] | VPN[0] | Page Offset |
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

-   **VPN[2], VPN[1], VPN[0]**：三级虚拟页号，每级占 9 位，共 27 位。

-   **Page Offset**：页内偏移，占 12 位。

-   **虚拟地址长度**：39 位。

### 3. 地址解析过程

地址解析的基本流程： 1. 从虚拟地址中提取 VPN[2]，查找第三级页表，获取下一级页表的物理地址。 2. 使用 VPN[1] 查找第二级页表。 3. 使用 VPN[0] 查找第一级页表，最终获取目标物理页帧。

### 4. 页表项（PTE）

页表项记录了一个虚拟页号对应的物理页帧信息，包括： - **物理页号（PPN）**：指向下一级页表或物理页帧。 - **权限位（Flags）**：读、写、执行权限等。

页表项的格式：

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
| PPN | Flags |
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

页表的核心数据结构
------------------

### 页表项（PTE）

在代码中，页表项由 `PageTableEntry` 结构表示：

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
pub struct PageTableEntry {
    entry: usize, // 页表项的值
}
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

#### 方法解析

1.  **创建新的页表项**  
    通过指定物理页号（PPN）和权限标志（Flags），创建一个新的页表项：

    ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
    pub fn new(ppn: usize, flags: usize) -> Self {
        Self {
            entry: (ppn << 10) | (flags & 0x3ff), // 高位存储物理地址，低位存储权限
        }
    }
    ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

2.  **提取物理页号（PPN）**  
    从页表项中提取物理页号：

    ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
    pub fn ppn(&self) -> usize {
        self.entry >> 10 // 高位为物理页号
    }
    ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

3.  **提取权限标志（Flags）**  
    从页表项中提取权限标志：

    ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
    pub fn flags(&self) -> usize {
        self.entry & 0x3ff // 低 10 位为权限标志
    }
    ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

完整代码如下：

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
impl PageTableEntry {
    pub fn new(ppn: usize, flags: usize) -> Self {
        Self {
            entry: (ppn << 10) | (flags & 0x3ff),
        }
    }
    pub fn ppn(&self) -> usize {
        self.entry >> 10
    }
    pub fn flags(&self) -> usize {
        self.entry & 0x3ff
    }
}
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

### 页表（PageTable）

页表使用数组结构存储页表项。每级页表包含 512 个页表项（对应 VPN 的 9 位范围）。

#### 核心定义

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
pub struct PageTable {
    entries: [PageTableEntry; 512], // 每个页表包含 512 个页表项
}
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

存储管理模块 - 地址空间管理
===========================

简介
----

地址空间管理是操作系统内存管理中的核心功能，用于将虚拟地址映射到物理地址，并提供灵活的逻辑段管理。每个地址空间包含多个逻辑段（Segment），用于组织程序的代码、数据、堆、栈等不同用途的内存区域。

在本项目中，地址空间管理由 `src/mm/memory_set.rs` 文件实现，核心功能包括： - 定义逻辑段。 - 管理虚拟地址到物理地址的映射。 - 支持动态调整地址空间的布局。

本节将通过理论介绍与代码解析相结合的方式，详细阐述地址空间的设计与实现。

地址空间的基本概念
------------------

### 地址空间的结构

地址空间由多个逻辑段组成，每个逻辑段包含以下关键信息： - **起始地址与结束地址**：定义逻辑段在虚拟地址空间中的范围。 - **权限**：控制逻辑段的访问属性，如可读、可写、可执行。 - **映射类型**：定义逻辑段如何与物理内存关联（直接映射或按需映射）。

地址空间结构在操作系统中的主要用途包括： - 将用户程序的代码、数据、堆和栈等分配到独立的虚拟地址空间。 - 提供对内核和用户地址空间的隔离，确保系统安全性。

### 地址空间的组成部分

1.  **逻辑段（Segment）**  
    一个逻辑段表示一段连续的虚拟地址范围，并与物理地址关联。

2.  **页表（Page Table）**  
    页表存储虚拟地址与物理地址的映射关系，是地址空间的重要组成部分。

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
pub fn map_segment(&mut self, segment: Segment) {
    let start_vpn = segment.start.page_number();
    let end_vpn = segment.end.page_number();
    for vpn in start_vpn..end_vpn {
        self.page_table.map(vpn, vpn, segment.flags.bits());

    self.segments.push(segment);
}
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

存储管理模块 - 动态内存分配（堆分配器）
=======================================

简介
----

动态内存分配是操作系统为程序提供灵活内存分配能力的关键功能。通过动态分配，操作系统可以在程序运行时根据需求分配或释放内存，避免静态内存分配的限制。

在本项目中，动态内存分配由 `src/mm/heap_allocator.rs` 文件实现，使用堆分配器（Heap Allocator）管理动态内存。堆分配器的核心功能包括： - 为操作系统内核提供灵活的动态内存分配支持。 - 使用高效的分配算法，减少内存碎片。

本节将详细分析堆分配器的设计与实现，并通过代码解析堆分配的核心功能。

动态内存分配的基础概念
----------------------

### 堆内存

堆内存是一块由操作系统管理的内存区域，用于在程序运行时动态分配。堆内存具有以下特点： - **灵活性**：在运行时按需分配或释放。 - **碎片问题**：由于分配和回收的动态性，可能产生内存碎片。

### 堆分配器的设计目标

1.  **高效性**：减少分配与释放的时间开销。

2.  **低碎片率**：尽可能减少内存碎片。

3.  **线程安全**：支持并发环境中的内存分配。

堆分配器的核心数据结构
----------------------

堆分配器由 `HeapAllocator` 结构体表示，用于管理整个堆内存区域。

### 核心定义

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
pub struct HeapAllocator {

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

-   `heap_start` **和** `heap_end`：堆的地址范围。

### 初始化堆分配器

-   参数 `size`：堆的大小。

### 分配内存

#### 分配逻辑

堆分配器通过 `alloc` 方法分配指定大小的内存块，并返回其起始地址：

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ rust
pub fn alloc(&mut self, size: usize) -> Option<usize> {
    let alloc_start = self.current;
    let alloc_end = self.current + size;

    if alloc_end > self.heap_end {
        None // 内存不足，分配失败
    } else {
        self.current = alloc_end; // 更新当前分配位置
        Some(alloc_start) // 返回分配的起始地址
    }
}
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

-   `alloc_start`：当前的分配位置。

-   `alloc_end`：计算分配后的结束位置。

-   如果 `alloc_end` 超过 `heap_end`，返回 `None` 表示分配失败；否则更新 `current` 并返回分配地址。

#### 示例代码


虽然本模块已实现了存储管理的核心功能，但仍存在进一步优化和扩展的空间：

1. **改进动态内存分配**  
   - 实现更复杂的分配算法（如最佳适配、最差适配）。
   - 支持分配内存的回收，减少内存碎片。

2. **完善权限控制**  
   - 增加更细粒度的权限控制机制，进一步提升内存的安全性。

3. **内存共享与虚拟内存**  
   - 实现跨任务的内存共享机制。
   - 支持虚拟内存功能，包括页面置换和交换。

4. **多任务支持**  
   - 扩展地址空间管理模块，支持多任务环境下的地址空间切换。
