## 进程管理设计思想

进程管理模块的实现围绕进程控制块（PCB）展开。

### 进程控制块的基本信息

- **进程标识符（PID）**：用于唯一标识每个进程，方便在系统范围内对不同进程进行区分、查找以及资源关联等操作，例如可以采用整数类型自增的方式来分配唯一的 PID。
- **进程状态**：定义一个枚举类型来表示进程所处的不同状态，一共有创建（Create）就绪（Ready）、运行（Running）、阻塞（Blocked）、终止（Stopped）五个状态，便于系统根据状态进行相应的调度决策和资源管理。
- **父进程与子进程关系**：通过记录进程控制块的信息记录进程的父进程以及子进程列表，方便在父进程等待子进程结束、子进程继承父进程部分资源等操作时进程创建、终止管理进程之间的层级关系。

### 执行相关信息

- **程序计数器（PC）**：保存进程当前执行到的指令地址，当进程切换出去再恢复执行时，能依据此地址继续准确地执行后续指令，确保程序执行的连贯性。
- **寄存器状态**：需要记录进程运行时各个通用寄存器、状态寄存器等的内容，在任务切换时保存当前进程的寄存器值，并在下次恢复执行时将这些值还原到相应寄存器中，使得进程继续执行。
- **栈相关信息**：包含用户栈和内核栈相关的指针、大小等信息。用户栈用于进程在用户态函数调用、局部变量存储等操作；内核栈则在进程进入内核态（比如进行系统调用、处理中断等情况）时使用，保障栈空间的正确使用以及不同特权级下的函数调用等操作顺利进行。

### 进程创建

1. **分配 PID**：从全局的 PID 分配器获取一个尚未使用的 PID 分配给新进程，确保每个进程都有唯一的标识符。
2. **初始化内存空间**：为进程分配内存，构建相应的内存映射关系，涉及从磁盘加载程序代码和数据到内存、设置堆、栈等内存区域的初始状态等操作。
3. **设置初始状态**：将进程状态初始化为就绪（Ready）状态，表示其已准备好被调度执行；同时初始化程序计数器指向程序的入口地址，寄存器等执行相关信息设置为默认值（清空），并初始化栈空间、文件描述符表（继承父进程部分或者初始化为标准输入输出对应的描述符）。
4. **关联父子进程关系**：如果通过父进程使用 `fork` 创建子进程，则需要在父进程和子进程的相关字段中记录彼此的关系，在子进程中记录父进程的引用，在父进程中将子进程添加到其子进程列表中。

### 进程调度

1. **调度策略选择**：我们采用先来先服务+时间片轮转的思想，选择下一个执行进程。
2. **就绪队列管理**：维护就绪队列，用于存放处于就绪状态的进程，当有进程进入就绪状态时将其添加到相应队列中，调度器从这些队列中按照调度策略选取进程运行。
3. **进程切换操作**：当需要进行进程切换时（当前运行进程的时间片用完），需要保存当前正在运行进程的上下文信息到其对应的 PCB 中，然后从就绪队列中选取下一个要执行的进程，将该进程的上下文信息恢复到硬件寄存器等相关位置，使得下一个进程可以开始执行，这个切换过程我们借助底层的汇编代码实现，确保切换的正确性和高效性。

### 进程终止

1. **资源回收**：释放进程所占用的各种资源，包括内存空间、关闭打开的文件，并将其占用的其他系统资源进行清理回收，避免资源泄漏。
2. **更新父子进程关系**：通知父进程子进程已经终止，若父进程正在等待子进程结束，唤醒父进程进行相应的处理；同时将子进程从父进程的子进程列表中移除。
3. **PCB 释放**：最后将进程对应的 PCB 结构体所占用的内存空间释放掉，完成整个进程的终止流程，使其彻底从系统中移除。

## 进程管理流程：

### 初始化

在内核入口函数中，执行`task::init()`函数，其作用是初始化任务管理器，并将系统的第一个进程：INIT_PROC进程添加到任务管理器的就绪队列中，并为其创建一个进程控制块，进程状态从`Create`状态更改为`Ready`状态，其中INIT_PROC的代码和数据来自 initproc 只读文件。由于最先加入到就绪队列的是INIT_PROC任务，所以优先执行INIT_PROC任务。

### 任务的创建：

除了INIT_PROC以外的所有任务都是由user/src中的sh文件产生的，它的作用是使用`get_command`接收用户输入的命令，使用`fork`（返回值为0时表示子进程）创建对应命令的进程。

### 任务的执行

在用户程序中，我们已经通过sh.rs创建了任务，接着对`pid`进行判断，如果是子进程（`fork`==0），则执行`execve`函数产生名为`sys_execve`（用来执行相应的任务）的系统调用；如果是父进程（`fork!`=0），则等待子进程执行完毕，并显示出相关的信息。

### 任务的调度

1. 为了实现时间片轮转的调度算法，我们采用抢占式调度，通过定时器中断产生信号，因此，需要通过执行`enable_timer_interrupt`函数开启定时器中断，并执行`set_next_timeout(trap::handler::TIMER_INTERVAL_USEC)`设置下一次定时器中断的时间。
2. 接着，执行`run_tasks`函数（实现对当前的Processor对象的字段的更新），这个函数会不断循环，尝试从任务管理器中获取任务并运行。在执行任务之前，需要先获取空闲任务上下文指针，获取任务的PCB，从PCB中获取当前任务上下文的指针。然后将进程状态从`Ready`状态更改为`Running`状态表示进程正在执行，接着将`Processor`对象的`current`（当前正在运行的任务）设置为刚刚获取到的任务，并把`Processor`对象的`idle_ctx`设置为获取到的任务上下文，从而实现对任务的调度。

## 进程管理模块实现：

### Context：任务上下文模块

**模块描述：**

`TaskCtx`模块主要用于处理任务上下文相关的操作，任务上下文包含了任务执行时的寄存器信息，在任务切换、中断处理等场景中起着关键作用。

#### TaskCtx结构体

**字段描述：**

- `ra`：用于保存返回地址，其类型为`usize`，存放着相关的内存地址信息。
- `sp`：代表栈指针，同样是`usize`类型，指向任务对应的栈空间位置，对函数调用、局部变量存储等栈相关操作有着重要意义。
- `s`：是一个包含 12 个`usize`元素的数组，用于保存其他相关的寄存器信息。

#### default函数

在需要创建一个默认初始状态的`TaskCtx`实例时，可以使用`TaskCtx::default()`来获取，并把`ra`、`sp`以及数组`s`中的所有元素都初始化为 0。

#### goto_trap_return函数

该函数用于创建一个新的`TaskCtx`实例，并将其初始化为陷阱返回状态。它接收一个参数`kernel_stack_ptr`，此参数代表内核栈指针的地址。

**返回值说明**：

- `ra`被设置为`trap_return`函数的地址（通过`ra: trap_return as usize`实现），这使得任务在后续执行到相应阶段时能正确返回到陷阱处理后的逻辑中。
- `sp`被设置为传入的`kernel_stack_ptr`，将栈指针指向指定的内核栈位置，确保栈操作的正确性。
- `s`寄存器数组被初始化为 0，保证相关寄存器处于初始状态。

### Manager：任务管理器模块

**模块描述：**

`TaskManager`模块提供了一套较为完整的任务管理相关操作，从任务的入队、出队，到任务切换以及替换等功能都有对应的函数实现，用于在整个系统中有效地管理任务执行流程。

#### 任务管理器结构体

`TaskManager`结构体用于管理任务相关操作，主要围绕就绪队列来对任务进行处理。

#### new函数

用于创建一个新的任务管理器实例，初始化时会创建一个空的就绪队列。

#### put函数

将给定的任务放入任务管理器的就绪队列中，通过调用`self.ready_queue.push_back(task)`实现将任务添加到队列末尾的操作。

#### get函数

从就绪队列中取出一个任务，具体是从队列头部取出（通过`self.ready_queue.pop_front()`实现），返回值为`Option`类型，如果队列中有任务则返回`Some(task)`，若队列为空则返回`None`。

#### put_task函数

将任务放入全局任务管理器的就绪队列。其实现过程先是获取全局任务管理器实例（通过`let mut this = TASK_MANAGER.ref_cell.borrow_mut();`），然后调用内部的`put`函数将任务添加到就绪队列中。

#### get_task函数

从全局任务管理器的就绪队列中取出任务。同样先获取全局任务管理器实例（`let mut this = TASK_MANAGER.ref_cell.borrow_mut();`），再调用内部的`get`函数来获取任务，返回值也是`Option`类型，根据队列情况返回相应结果。

#### cycle_to_next函数

实现将当前任务切换到下一个任务的功能。

**具体步骤**：

1. 首先获取当前任务（`let task = Processor::take_current().unwrap();`）。

2. 接着修改当前任务的状态为`Ready`（通过修改其对应的`ProcessControlBlock`中的状态字段）。

3. 将当前任务放入全局任务管理器的就绪队列（`TaskManager::put_task(task);`）。
4. 最后调用处理器相关的调度函数（`Processor::schedule(ctx);`）来进行任务调度。

**源代码：**

```rust
pub fn cycle_to_next() {
    let task = Processor::take_current().unwrap();
    
    let mut pcb = task.inner_borrow_mut();
    let ctx = &mut pcb.ctx as *mut TaskCtx;
    pcb.status = ProcessStatus::Ready;
    drop(pcb);
    
    TaskManager::put_task(task);
    Processor::schedule(ctx);
}
```

#### replace_to_next函数

将当前任务替换为下一个任务，并设置退出码。

**具体步骤：**

1. 获取当前任务（`let task = Processor::take_current().unwrap();`），然后修改其对应的`ProcessControlBlock`中的相关属性，比如设置退出码（`pcb.exit_code = exit_code;`）、修改状态为`Stopped`（`pcb.status = ProcessStatus::Stopped;`）等。
2. 对任务的子进程等相关资源进行清理和重新分配操作，例如修改子进程的父进程指向、回收内存等操作。
3. 最后调用处理器相关的调度函数（`Processor::schedule(&mut _unused as *mut _);`）来触发下一次任务调度。

**源代码：**

```rust
pub fn replace_to_next(exit_code: i32) {
    let task = Processor::take_current().unwrap();
    let mut pcb = task.inner_borrow_mut();
    pcb.exit_code = exit_code;
    pcb.status = ProcessStatus::Stopped;
    let mut initproc = INIT_PROC.inner_borrow_mut();
    for child in pcb.children.iter() {
        child.inner_borrow_mut().parent = Some(Arc::downgrade(&INIT_PROC));
        initproc.children.push(child.clone());
    }
    drop(initproc);
    pcb.children.clear();
    pcb.memory_set.recycle();
    drop(pcb);
    drop(task);
    let mut _unused = TaskCtx::default();
    Processor::schedule(&mut _unused as *mut _);
}
```

### Mod：任务模块

**模块描述：**

“任务模块” 在整个系统中承担着管理任务相关操作的重要职责，涵盖了任务的初始化、任务管理器的使用以及与进程控制块等相关联的诸多功能，为系统中任务的有序执行和调度奠定基础。

#### init函数

该函数的主要功能就是将前面定义的`INIT_PROC`实例添加到任务管理器中（通过调用`TaskManager::put_task`函数并传入`INIT_PROC`的克隆副本），以此来开启任务管理的初始化流程，后续任务管理器便可以基于这个初始任务进行更多的任务调度、执行等相关操作。

### Pid：进程id分配器模块

**模块描述：**

该模块主要负责进程 ID（PID）的分配与回收管理，通过合理的机制确保在系统运行过程中，能够有效地为新创建的进程分配唯一可用的 PID，并在进程结束时正确回收 PID，以供后续其他进程使用。

该 PID 分配器模块构建起了一套较为完善的 PID 管理机制，既能合理分配 PID，又能妥善处理 PID 的回收工作，并且借助 Rust 的语言特性保证了资源管理的安全性和可靠性，在整个系统中为进程的创建、销毁等涉及 PID 使用的环节提供了有力支持。

#### PidHandler结构体

`PidHandler`结构体简单地包装了一个`usize`类型的成员，用于表示进程 ID，通过这种结构体的形式，可以在后续操作中方便地传递和管理 PID，同时也可以在其上添加更多与 PID 相关的行为和函数。

#### PidAllocator结构体

`PidAllocator`结构体是整个 PID 分配机制的核心数据结构。

**字段描述：**

- `unused`：是一个`Range<usize>`类型，表示未使用的 PID 范围，通过定义这样一个范围，可以清晰地知道当前还有哪些 PID 是可以分配给新进程的。
- `recycled`：是一个`Vec<usize>`类型，即动态大小的`usize`数组，用于存储已经回收的 PID，这些回收的 PID 可以在后续分配时优先被使用，提高 PID 的利用率。

#### new函数

`new`函数用于创建一个新的`PidAllocator`实例，在初始化时，会设定初始的未使用 PID 范围为从`0`到`usize::MAX - 256`，意味着预留了最后的`256`个 PID 暂不参与分配，同时初始化一个空的回收 PID 列表。

#### alloc方法

`alloc`函数用于分配一个新的 PID。

**具体步骤：**

1. 首先会优先查看回收的 PID 列表`recycled`，如果列表中有可用的 PID（通过`self.recycled.pop()`获取），则直接将其包装成`PidHandler`结构体并返回。
2. 若回收列表为空，则会检查未使用的 PID 范围`unused`，如果范围还有可用的 PID（即`self.unused.start < self.unused.end`），那么取出范围起始的 PID，同时更新范围起始值（`self.unused.start += 1`），再将其包装成`PidHandler`返回。
3. 如果上述两种情况都无法获取到可用的 PID，则返回`None`，表示当前没有 PID 可供分配了。

**源代码：**

~~~rust
fn alloc(&mut self) -> Option<PidHandler> {
    if let Some(pid) = self.recycled.pop() {
        return Some(PidHandler(pid));
    }
    if self.unused.start < self.unused.end {
        let pid = self.unused.start;
        self.unused.start += 1;
        return Some(PidHandler(pid));
    }
    None
}
~~~

#### dealloc方法

`dealloc`函数用于释放一个已经使用过的 PID。

**具体步骤：**

1. 首先判断要释放的 PID 是否在未使用的 PID 范围中，如果是（`pid >= self.unused.start`），则会触发`panic`，因为这意味着尝试释放一个原本就未分配出去的 PID，属于错误操作。
2. 接着检查该 PID 是否已经存在于回收列表中，如果已经存在（通过`self.recycled.iter().any(|&f| f == pid)`判断），同样会触发`panic`，避免重复回收同一个 PID。
3. 当上述检查都通过后，会将该 PID 添加到回收列表`recycled`中，使其可以在后续分配时被再次利用。

**源代码：**

~~~rust
fn dealloc(&mut self, pid: usize) {
    if pid >= self.unused.start {
        panic!("尝试释放未分配的 PID: {:?}", pid);
    }
    if self.recycled.iter().any(|&f| f == pid) {
        panic!("尝试释放已释放的 PID: {:?}", pid);
    self.recycled.push(pid);
}
~~~

#### alloc_pid方法

`alloc_pid`函数是对外提供的一个便捷函数，用于分配一个新的 PID 并返回对应的`PidHandler`结构体。它通过获取全局的`PID_ALLOCATOR`（这是一个使用`lazy_static`定义的静态变量，保证全局唯一且延迟初始化），然后调用其内部的`alloc`函数来获取 PID，如果分配成功则返回对应的`PidHandler`，若分配失败（返回`None`）则会触发`unwrap`产生`panic`，表示当前没有可用的 PID 是不符合预期的情况。

#### Drop实现

为`PidHandler`结构体实现了`Drop` trait，这意味着当`PidHandler`实例在离开作用域被销毁时，会自动触发`drop`函数，进而调用`PID_ALLOCATOR`的`dealloc`函数来释放对应的 PID，确保资源能够及时、正确地被回收，无需手动干预。

### Processor：处理器模块

**模块描述：**

处理器模块在整个系统架构中起着核心的调度与任务管理作用，它负责协调各个任务（以进程控制块表示）的执行顺序、状态切换，以及与任务上下文、陷阱上下文等相关信息的交互，确保系统中任务能够有序且高效地运行。

#### Processor结构体

**字段描述：**

- `current`：是一个`Option`类型，包裹着`Arc<SyncRefCell<ProcessControlBlock>>`，用于表示当前正在运行的任务。`Option`类型可以方便地处理当前没有任务运行（值为`None`）或者有任务正在运行（值为`Some(task)`）的不同情况。
- `idle_ctx`：是`TaskCtx`类型，代表空闲任务上下文，用于在任务切换等操作中保存和恢复空闲状态下的相关寄存器等信息。

#### new方法

`new`函数用于创建一个新的`Processor`实例，初始化时将`current`设置为`None`，表示当前没有正在运行的任务，而`idle_ctx`则通过调用`TaskCtx::default()`初始化为默认的任务上下文，其各个寄存器相关字段都被初始化为 0。

#### get_idle_ctx_ptr方法

该函数用于获取空闲任务上下文的指针，通过将`&mut self.idle_ctx`转换为原生指针类型`*mut TaskCtx`，以便在后续需要直接操作指针的地方（比如任务切换函数中）使用，传递相关的上下文地址信息。

####  run_tasks方法

`run_tasks`函数实现了一个无限循环来持续运行任务的逻辑。

**具体步骤：**

在每次循环中：

1. 首先通过可变借用获取全局处理器实例（`let mut this = PROCESSOR.inner_borrow_mut();`）。

2. 然后尝试从任务管理器中获取一个任务`if let Some(task) = TaskManager::get_task()`，如果获取到任务，则进行以下操作：

   - 获取空闲任务上下文的指针（`let idle_ctx = this.get_idle_ctx_ptr();`）。
   - 获取任务对应的进程控制块并进行可变借用（`let mut pcb = task.inner_borrow_mut();`），接着获取任务上下文的指针（`let next_ctx = &pcb.ctx as *const TaskCtx;`），同时将进程状态设置为`Running`（`pcb.status = ProcessStatus::Running;`），最后释放进程控制块的可变借用（`drop(pcb)`）。
   - 将获取到的任务设置为当前正在运行的任务（`this.current = Some(task);`），并释放对处理器实例的可变借用（`drop(this)`）。

3. 最后通过`unsafe`块调用`__switch`函数，利用空闲任务上下文指针和下一个任务的上下文指针来进行实际的任务切换操作，从而让获取到的任务开始运行。

**源代码：**

```rust
pub fn run_tasks() {
    loop {
        let mut this = PROCESSOR.inner_borrow_mut();
        if let Some(task) = TaskManager::get_task() {
            let idle_ctx = this.get_idle_ctx_ptr();
            let mut pcb = task.inner_borrow_mut();
            let next_ctx = &pcb.ctx as *const TaskCtx;
            pcb.status = ProcessStatus::Running;
            drop(pcb);
            this.current = Some(task);
            drop(this);
            unsafe {
                __switch(idle_ctx, next_ctx);
            }
        }
    }
}
```

#### schedule方法

`schedule`函数用于调度任务，接收一个要切换的任务上下文指针`switched_task_cx_ptr`作为参数。

**具体步骤：**

1. 先通过可变借用获取全局处理器实例，并获取空闲任务上下文的指针（`let mut this = PROCESSOR.inner_borrow_mut();`和`let idle_ctx = this.get_idle_ctx_ptr();`）。
2. 然后释放对处理器实例的可变借用（`drop(this)`）。
3. 最后在`unsafe`块中调用`__switch`函数，传入要切换的任务上下文指针和空闲任务上下文指针，完成任务的调度切换操作，使得系统可以切换到其他任务或者回到空闲状态。

**源代码：**

```rust
pub fn schedule(switched_task_cx_ptr: *mut TaskCtx) {
        let mut this = PROCESSOR.inner_borrow_mut();
        let idle_ctx = this.get_idle_ctx_ptr();
        drop(this);
        unsafe {
            __switch(switched_task_cx_ptr, idle_ctx);
        }
}
```

#### take_current方法

该函数用于获取当前正在运行的任务，并将其从处理器的当前任务记录中移除（通过调用`take`函数）。它通过可变借用全局处理器实例中的`current`字段来实现，返回值为`Option`类型，如果当前有正在运行的任务则返回`Some(task)`，否则返回`None`。

#### get_current方法

`get_current`函数用于获取当前正在运行任务的引用。它通过不可变借用全局处理器实例中的`current`字段，先判断是否有当前任务（通过`as_ref`），如果有则通过`map`和`Arc::clone`返回一个克隆后的任务引用，同样返回值为`Option`类型，方便外部代码根据情况进行处理。

**源代码：**

```rust
pub fn get_current() -> Option<Arc<SyncRefCell<ProcessControlBlock>>> {
    PROCESSOR
       .ref_cell
       .borrow()
       .current
       .as_ref()
       .map(|pcb| Arc::clone(pcb))
}
```

#### current_user_token方法

该函数用于获取当前用户的令牌。首先调用`get_current`函数获取当前正在运行的任务，如果获取成功（`let current = Self::get_current()?;`），则通过可变借用任务的进程控制块（`current.ref_cell.borrow_mut()`），再调用其内部的`get_user_token`函数来获取用户令牌，最后将获取到的令牌包装在`Some`中返回，如果当前没有正在运行的任务则返回`None`。

**源代码：**

```rust
pub fn current_user_token() -> Option<usize> {
    let current = Self::get_current()?;
    let token = current.ref_cell.borrow_mut().get_user_token();
    Some(token)
}
```

#### current_trap_cx方法

此函数用于获取当前陷阱上下文。先获取当前正在运行的任务（`let current = Self::get_current()?;`），然后通过可变借用该任务的进程控制块，调用其内部的`get_trap_cx`函数来获取陷阱上下文的引用，最后将获取到的引用包装在`Some`中返回，如果当前没有正在运行的任务则返回`None`。

**源代码：**

```rust
pub fn current_trap_cx() -> Option<&'static mut TrapCtx> {
    let current = Self::get_current()?;
    let trap_cx = current.ref_cell.borrow_mut().get_trap_cx();
    Some(trap_cx)
}
```

### Stack：进程栈模块

**模块描述：**

进程栈管理模块聚焦于对进程中栈相关资源的管理操作，涵盖了内核栈位置的计算、内核栈的创建与销毁，以及向内核栈中压入数据等功能，在整个进程管理体系里为栈空间的合理分配与使用提供了有效的支持。

进程栈管理模块围绕内核栈构建起了从创建、使用到销毁的完整生命周期管理机制，合理地处理了内存映射、数据操作以及资源回收等关键环节，为进程在内核层面的栈相关操作提供了可靠且便捷的支持，在整个进程运行及管理的流程中有着不可或缺的作用。

#### kernel_stack_position函数

该函数用于根据给定的进程 ID（`pid`）来计算内核栈的位置，返回一个包含栈底和栈顶地址的元组。计算方式是通过`TRAMPOLINE`地址减去基于进程 ID、内核栈大小以及页面大小（`PAGE_SIZE_SV39`）计算得出的偏移量来确定栈顶地址，然后再通过栈顶地址减去内核栈大小得到栈底地址，这样就能明确每个进程对应的内核栈在内存中的具体位置范围。

**源代码：**

```rust
pub fn kernel_stack_position(pid: usize) -> (usize, usize) {
    let top = TRAMPOLINE - pid * (KERNEL_STACK_SIZE + PAGE_SIZE_SV39);
    let bottom = top - KERNEL_STACK_SIZE;
    (bottom, top)
}
```

#### KernelStack结构体

`KernelStack`结构体用于表示内核栈，其内部仅包含一个成员`pid`，用于记录所属进程的 ID，通过这个 ID 可以关联到特定进程的内核栈，并在后续的各种操作（如获取栈顶地址、压入数据等）中使用它来确定具体的操作对象。

#### new方法

`new`函数用于创建一个新的内核栈实例。它接收一个`PidHandler`类型的参数（通过`pid.0`获取其中的进程 ID），首先调用`kernel_stack_position`函数计算出对应进程的内核栈位置（栈底和栈顶地址），然后借助`KERNEL_SPACE`（很可能是内核空间管理相关的结构），通过可变借用其内部资源，在对应的虚拟地址范围内（从栈底到栈顶）插入一个具有读写权限（`MapPermission::Read | MapPermission::Write`）的内存映射，以此来为该进程分配内核栈的内存空间，最后创建并返回一个包含对应进程 ID 的`KernelStack`实例。

**源代码：**

```rust
impl KernelStack {
    pub fn new(pid: &PidHandler) -> Self {
        let (bottom, top) = kernel_stack_position(pid.0);
        KERNEL_SPACE.ref_cell.borrow_mut().insert(
            VirtualAddress::from(bottom)..VirtualAddress::from(top),
            MapPermission::Read | MapPermission::Write,
        );
        Self { pid: pid.0 }
    }
}
```

#### top方法

`top`函数用于获取内核栈的栈顶地址。它根据当前`KernelStack`实例中记录的进程 ID（`self.pid`），再次调用`kernel_stack_position`函数来获取对应的栈顶地址，并将其返回，方便后续在向栈中压入数据等操作时确定写入的起始位置。

**源代码：**

```rust
pub fn top(&self) -> usize {
    let (_bottom, top) = kernel_stack_position(self.pid);
    top
}
```

#### push法

`push`函数用于向内核栈中压入一个满足`Sized`约束的类型的值（`data`），并返回栈中该值的可变引用（以指针形式`*mut T`返回）。

**具体步骤：**

1. 首先获取当前内核栈的栈顶地址（`let top = self.top();`）。
2. 然后确定要压入值的类型`T`的大小（`let size = core::mem::size_of::<T>();`），虽然代码中还有获取对齐相关信息的部分（注释掉了），但核心逻辑是通过栈顶地址减去类型大小来计算出压入数据后的新栈顶位置（`let new_top = top - size;`）。
3. 将新栈顶位置转换为对应类型的可变指针（`let ptr = new_top as *mut T;`）。
4. 通过`unsafe`块将传入的数据写入到该指针指向的内存位置（`*ptr = data;`），完成数据压入操作，最后返回这个指针，以便外部代码可以通过该指针进一步操作压入栈中的数据（例如修改其内容等）。

**源代码：**

```rust
pub fn push<T>(&self, data: T) -> *mut T
where
    T: Sized,
{
    let top = self.top();
    let size = core::mem::size_of::<T>();
    let new_top = top - size;
    let ptr = new_top as *mut T;
    unsafe {
        *ptr = data;
    }
    ptr
}
```

#### Drop实现

为`KernelStack`结构体实现了`Drop` trait，这意味着当`KernelStack`实例在离开作用域被销毁时，会自动触发`drop`函数。在`drop`函数内部，会根据当前内核栈实例对应的进程 ID（`self.pid`），调用`kernel_stack_position`函数获取其栈底和栈顶地址，然后借助`KERNEL_SPACE`相关的操作，从对应的虚拟页号（通过栈底地址转换而来）开始移除该内核栈所占用的内存区域，实现内存资源的自动回收，避免内存泄漏等问题。

**源代码：**

```rust
impl Drop for KernelStack {
    fn drop(&mut self) {
        let (bottom, top) = kernel_stack_position(self.pid);
        KERNEL_SPACE
           .ref_cell
           .borrow_mut()
           .remove_area(VirtualPageNumber::from(VirtualAddress::from(bottom)));
    }
}
```

### Switch：任务切换模块

**模块描述：**

任务切换模块在整个系统的任务管理体系中起着至关重要的作用，它负责实现不同任务之间的上下文切换操作，通过与底层汇编代码协作以及定义外部函数接口，为上层的任务调度逻辑提供了关键的切换功能支持，确保系统能够在多个任务间流畅地进行切换执行。

任务切换模块通过结合 Rust 代码与汇编代码，利用`TaskCtx`结构体来传递任务上下文信息，并借助声明的外部汇编函数`__switch`实现了具体的任务切换功能，为整个系统中多任务并发执行、任务调度等上层功能提供了坚实的底层支撑，是保障系统任务管理机制正常运作的关键环节。

#### 外部汇编函数声明

声明了一个外部的汇编函数`__switch`，该函数接收两个指针参数：

- `current`：是一个指向当前任务上下文的指针（类型为`*mut TaskCtx`），通过这个指针，函数可以访问和操作当前任务的上下文信息，例如保存当前任务的寄存器状态等内容，以便后续切换回来时能恢复到正确的执行状态。
- `next`：是一个指向下一个任务上下文的指针（类型为`*const TaskCtx`），利用这个指针，函数可以获取下一个任务的上下文信息，进而将相关寄存器等状态恢复到硬件环境中，使得系统可以开始执行下一个任务。

### Task：任务管理模块

**模块描述：**

进程管理模块是整个系统中极为关键的部分，它围绕进程控制块（Process Control Block，PCB）这一核心数据结构，对进程的创建、状态管理、资源分配（如文件描述符、内存空间等）以及与父子进程相关的操作（如创建子进程、执行新程序等）进行了全面的管控，为系统中多个进程的有序运行提供了坚实的基础保障。

#### ProcessControlBlock结构体

`ProcessControlBlock`结构体是整个进程管理模块的核心数据结构，它全面地记录了与一个进程相关的各种关键信息。

**字段描述：**

- `pid`：通过`PidHandler`类型记录进程的唯一标识符，用于区分不同的进程，在进程调度、资源管理等多个环节都会依赖该 ID 进行相关操作。
- `kernel_stack`：使用`KernelStack`结构体表示进程对应的内核栈，涉及内核栈的创建、使用以及销毁等生命周期管理，为进程在内核态的函数调用、局部变量存储等操作提供栈空间支持。
- `status`：通过`ProcessStatus`枚举类型来标识进程当前所处的状态，便于系统根据状态进行相应的调度和管理决策，例如将就绪状态的进程投入运行等操作。
- `ctx`：保存任务上下文信息的`TaskCtx`结构体，在任务切换等操作中起着关键作用，确保进程切换时能正确恢复和保存执行现场的寄存器等关键信息。
- `memory_set`：代表进程的内存集合，通过`MemorySet`类型管理进程所占用的内存空间，包括内存的分配、映射以及地址转换等相关操作，确保进程在合法的内存范围内进行数据读写等操作。
- `trap_ctx_ppn`：记录陷阱上下文的物理页号，用于在处理中断、异常等陷阱情况时准确地定位和操作相关的内存页面，与底层的硬件异常处理机制紧密相关。
- `base_size`：存储一个基础大小相关的`usize`值，其具体含义可能与进程的内存布局、初始栈大小或者其他与内存使用相关的基准量有关，具体取决于整个系统的设计逻辑。
- `parent`：使用`Option<Weak<SyncRefCell<ProcessControlBlock>>>`来表示父进程，通过弱引用（`Weak`）的方式避免循环引用，同时可以关联到父进程的相关信息，在诸如进程资源回收、继承关系处理等方面有重要作用。
- `children`：是一个`Vec<Arc<SyncRefCell<ProcessControlBlock>>>`类型的向量，用于存储该进程的所有子进程，方便对父子进程关系进行管理，例如在父进程结束时对子进程的处理等操作。
- `exit_code`：记录进程结束时的退出码，用于向父进程或者其他相关系统组件反馈进程执行的结果状态，通常在进程正常或异常结束后会设置相应的退出码值。
- `fd_table`：即前面定义的文件描述符表类型`FdTable`，用于管理进程打开的文件相关资源，通过文件描述符来索引对应的文件对象，实现对文件的读写等操作。

#### get_trap_cx方法

该函数用于获取陷阱上下文的可变引用，通过调用`self.trap_ctx_ppn`（陷阱上下文的物理页号相关操作）的`get_mut`函数来实现，返回的可变引用可以用于进一步修改陷阱上下文的相关内容，例如在初始化或者处理陷阱情况时更新其中的寄存器值等信息。

#### get_user_token函数

用于获取用户态的令牌，其实现是通过调用进程的内存集合（`memory_set`）的`token`函数来获取相应的值，具体这个令牌在整个系统中的作用可能与用户态权限管理、内存访问限制等方面相关，根据系统设计而定。

#### get_status函数

简单地返回进程当前的状态，通过直接访问`self.status`字段，外部代码可以方便地获取进程所处的状态信息，以便进行相应的流程控制和管理操作。

#### new函数

`new`函数用于创建一个新的进程控制块实例。

**具体步骤：**

1. 首先，根据传入的应用程序数据（`app_data`），通过`MemorySet::from_elf_app(app_data)`函数获取内存集合、用户栈指针（`user_sp`）以及程序入口地址（`entry`）等信息，用于初始化进程的内存相关属性。
2. 接着，通过`PidAllocator::alloc_pid()`分配一个新的进程 ID，并利用该 ID 创建对应的内核栈（`KernelStack::new(&pid)`），同时获取内核栈的栈顶地址（`kernel_stack_top`）。
3. 然后，构建一个初始状态的`ProcessControlBlock`实例，设置其进程 ID、内核栈、初始状态为`Ready`、任务上下文（通过`TaskCtx::goto_trap_return(kernel_stack_top)`根据栈顶地址初始化任务上下文）、内存集合、陷阱上下文的物理页号、基础大小以及初始的空子进程列表、默认退出码为 0，并初始化文件描述符表包含标准输入、输出等基本文件对象。
4. 最后，获取新创建的进程控制块的陷阱上下文引用（`pcb.get_trap_cx()`），并通过`TrapCtx::init_app_context`函数基于前面获取的程序入口地址、用户栈指针、内核空间令牌以及栈顶地址和陷阱处理函数地址等信息来初始化陷阱上下文，最终返回完整初始化后的进程控制块实例。

**源代码：**

```rust
pub fn new(app_data: &[u8]) -> Self {
    let (mut memory_set, user_sp, entry) = MemorySet::from_elf_app(app_data);
    let trap_ctx_ppn = PhysicalPageNumber::from(
        &memory_set
           .translate(VirtualPageNumber::from(VirtualAddress::from(TRAP_CONTEXT)))
           .unwrap(),
    );
    let pid = PidAllocator::alloc_pid();
    let kernel_stack = KernelStack::new(&pid);
    let kernel_stack_top = kernel_stack.top();

    let pcb = Self {
        pid,
        kernel_stack,
        status: ProcessStatus::Ready,
        ctx: TaskCtx::goto_trap_return(kernel_stack_top),
        memory_set,
        trap_ctx_ppn,
        base_size: user_sp,

            Some(Arc::new(Stdout)),
            Some(Arc::new(Stdout)),

        }
```
```rust
    }
```

#### fork函数

`fork`函数用于创建一个新的子进程，这个子进程会在很大程度上复制父进程的相关状态和资源配置，包括内存布局、文件描述符表等，同时具有自己独立的进程标识符、内核栈等关键元素，创建完成后子进程处于就绪状态，等待被调度执行。

**源代码：**

```rust
    pub fn fork(
        self: &Arc<SyncRefCell<ProcessControlBlock>>,
    ) -> Arc<SyncRefCell<ProcessControlBlock>> {
        let mut parent = self.inner_borrow_mut();
        let memory_set = MemorySet::from_existed_user(&parent.memory_set);
        let trap_ctx_ppn = PhysicalPageNumber::from(
            &memory_set
                .translate(VirtualPageNumber::from(VirtualAddress::from(TRAP_CONTEXT)))
                .unwrap(),
        );
        let pid = PidAllocator::alloc_pid();
        let kernel_stack = KernelStack::new(&pid);
        let kernel_stack_top = kernel_stack.top();
        let child = Arc::new(SyncRefCell::new(ProcessControlBlock {
            pid,
            kernel_stack,
            status: ProcessStatus::Ready,
            ctx: TaskCtx::goto_trap_return(kernel_stack_top),
            memory_set,
            trap_ctx_ppn,
            base_size: parent.base_size,
            parent: Some(Arc::downgrade(self)),
            children: Vec::new(),
            exit_code: 0,
            fd_table: parent.fd_table.fd_clone(),
        }));
        parent.children.push(child.clone());

        let ctx = child.inner_borrow().get_trap_cx();
        ctx.kernel_virt_sp = kernel_stack_top;

        child
    }
```

### Context：陷阱上下文模块

**模块概述：**

陷阱上下文模块在基于 RISC-V 架构的系统中起着关键作用，它主要围绕陷阱上下文（`TrapCtx`）结构体展开，用于处理系统在遇到中断、异常等陷阱情况时相关的上下文信息管理，包括寄存器状态保存、恢复以及基于不同应用场景的陷阱上下文初始化等操作，同时还通过定义相关特性（`trait`）来提供便捷统一的寄存器访问方式，为整个系统的陷阱处理机制奠定基础。

#### TrapCtx结构体

`TrapCtx`结构体是该模块的核心数据结构，用于保存陷阱发生时的关键上下文信息。

**字段描述：**

- `x`：是一个包含 32 个`usize`元素的数组，代表通用寄存器，涵盖了 RISC-V 架构下的多个通用寄存器，用于存储临时数据、运算结果等，在任务切换以及陷阱处理前后需要对这些寄存器的值进行保存和恢复，以确保程序执行的连贯性。
- `sstatus`：用于保存监管者状态寄存器的值，该寄存器记录了系统当前的一些状态信息，例如中断使能情况、特权模式等，在陷阱处理过程中其值的变化和恢复对于正确处理陷阱以及后续程序继续执行至关重要。
- `sepc`：即监管者异常程序计数器，它指向异常发生时的指令地址，当陷阱处理完成后，程序可以根据这个地址恢复到异常发生处继续执行，或者根据具体情况进行相应的跳转等操作。
- `kernel_satp`：存储内核页表基址寄存器的值，此寄存器与内存管理中的页表相关，用于定位内核空间的页表基地址，在陷阱处理涉及到内存访问以及不同特权级别的内存切换等场景中有重要作用。
- `kernel_virt_sp`：表示内核虚拟栈指针，指向内核虚拟栈的当前位置，栈在函数调用、局部变量存储以及陷阱处理过程中的现场保存等方面都有重要用途，该指针确保了在内核态处理陷阱时能正确地在栈上进行数据操作。
- `kernel_virt_trap_handler`：记录内核虚拟陷阱处理程序的地址，当陷阱发生时，程序流程会跳转到对应的陷阱处理程序，这个地址就是用于定位该处理程序的入口，确保能正确执行相应的陷阱处理逻辑。

#### set_sp方法

`set_sp`方法用于设置栈指针寄存器的值。它通过调用`self.sp()`（`TrapCtx`实现`Riscv64RegAlias`特性后，`sp`方法返回栈指针寄存器的可变引用）来获取对应的可变引用，然后将传入的`usize`类型的参数`sp`赋值给栈指针寄存器，实现对栈指针寄存器值的更新操作，这在调整栈指针位置、初始化栈相关状态等场景中会被用到。

#### init_app_context方法

`init_app_context`方法用于创建一个新的、适用于应用程序上下文的`TrapCtx`实例。

**具体步骤：**

1. **获取`sstatus`寄存器值**：
   由于`riscv` crate 没有提供从`sstatus`获取位的方法，所以使用内联汇编（`asm!("csrr {}, sstatus", out(reg) sstatus);`）来获取当前`sstatus`寄存器的值，并存储到局部变量`sstatus`中。这里使用`unsafe`块是因为内联汇编操作涉及直接与底层硬件寄存器交互，存在一定的安全性风险，需要开发者确保操作的正确性。
2. **清除`FS`位**：
   对获取到的`sstatus`值进行位操作，通过 `sstatus &=!(1 << 8);` 将`FS`位清除，这一步操作是根据具体的系统要求和陷阱处理相关逻辑来对状态寄存器进行初始化调整，确保其初始状态符合应用程序上下文的预期设置。
3. 构建`TrapCtx`实例并初始化部分字段，并初始化其各个字段：
   - `x`：初始化为全 0 的数组，表示通用寄存器初始状态为默认值 0，符合一般初始化时的预期情况。
   - `sstatus`：使用前面经过处理后的`sstatus`值进行初始化，将调整好的状态寄存器值设置到`TrapCtx`实例中。
   - `sepc`：设置为传入的程序入口地址（`entry`），这样当陷阱处理完成后，程序可以从这个指定的入口地址开始执行应用程序逻辑。
   - `kernel_satp`：直接使用传入的内核页表基址寄存器的值进行初始化，确保内存管理相关的页表基址设置正确。
   - `kernel_virt_sp`：使用传入的内核虚拟栈指针的值进行初始化，为内核态下的栈操作准备好正确的栈指针初始位置。
   - `kernel_virt_trap_handler`：使用传入的内核虚拟陷阱处理程序的地址进行初始化，以便在陷阱发生时能正确跳转到对应的处理程序入口。
4. **设置栈指针寄存器值**：
   调用`ctx.set_sp(sp);`，根据传入的栈指针地址（`sp`）来进一步设置`TrapCtx`实例中栈指针寄存器的值，完成整个`TrapCtx`实例针对应用程序上下文的初始化工作，最后返回这个初始化好的`TrapCtx`实例，供外部代码在创建应用程序相关的陷阱上下文场景中使用。

**源代码：**

```rust
impl TrapCtx {
    pub fn init_app_context(
        entry: usize,
        sp: usize,
        kernel_satp: usize,
        kernel_virt_sp: usize,
        kernel_virt_trap_handler: usize,
    ) -> Self {
        let mut sstatus: usize;
        unsafe {
            asm!("csrr {}, sstatus", out(reg) sstatus);
        }
        sstatus &=!(1 << 8);
        let mut ctx = Self {
            x: [0; 32],
            sstatus: sstatus,
            sepc: entry,
            kernel_satp,
            kernel_virt_sp,
            kernel_virt_trap_handler,
        };
        ctx.set_sp(sp);
        ctx
    }
}
```

### Handler：中断处理模块

**模块描述：**

中断处理模块在整个系统中扮演着至关重要的角色，它负责处理各种中断和异常情况，涵盖了用户态陷入、定时器中断以及其他可能出现的陷阱情况。通过对不同类型的中断和异常进行针对性处理，保障系统的稳定性以及任务的正常调度与执行，是维持系统运行秩序的关键部分。

中断处理模块通过一系列函数的协作，针对不同类型的中断和异常情况构建起了一套基本的处理机制，从陷阱的检测、分类处理到最终的返回用户态恢复执行等环节都有相应的逻辑实现，虽然部分功能（如某些异常情况的具体处理）还处于待完善状态，但整体为系统在面对各种中断和异常时保障稳定性和正常运行提供了重要的基础框架，在整个系统的可靠性保障方面起着关键作用。

#### trap_handler函数

此函数是整个中断处理模块的核心入口，用于处理各种用户态陷入的情况，也就是在用户态执行过程中发生的中断或异常情况。它通过读取相关寄存器的值判断具体的异常或中断类型，然后进行相应的处理操作，处理完成后再返回到用户态继续执行后续程序逻辑。

**实现步骤：**

1. **设置用户态陷阱入口**：调用`set_user_trap_entry`函数，修改`stvec`寄存器，将用户态陷阱入口指向`TRAMPOLINE`地址，并设置陷阱模式为直接模式。
2. **读取陷阱原因**：通过`scause::read().cause()`和`stval::read()`读取陷阱原因和相关额外信息。
3. **根据陷阱类型处理**：
   - **用户态环境调用异常**：获取陷阱上下文，增加程序计数器跳过`ecall`指令，调用`syscall`函数处理系统调用，重新获取陷阱上下文，将返回值存入`a0`寄存器。
   - **存储错误或页错误异常**：标记为`todo!`，需要补充逻辑以终止进程。
   - **非法指令异常**：标记为`todo!`，需要补充逻辑以终止进程。
   - **监督者定时器中断**：设置下一个定时器中断时间，通过`TaskManager::cycle_to_next()`进行任务切换。
   - **未处理的陷阱**：触发`panic`，输出错误信息。
4. **返回用户态**：调用`trap_return`函数，返回用户态继续执行程序。

**源代码：**

```rust
#[unsafe(no_mangle)]
pub fn trap_handler() ->! {
    set_user_trap_entry();
    let scause = scause::read().cause();
    let stval = stval::read();
    match scause {
        scause::Trap::Exception(const { Exception::UserEnvCall as usize }) => {
            let ctx = Processor::current_trap_cx().unwrap();
            ctx.sepc += 4;
            let ret = syscall(Syscall::from(*ctx.a(7)), [*ctx.a(0), *ctx.a(1), *ctx.a(2)]);
            let ctx = Processor::current_trap_cx().unwrap();
            *ctx.a(0) = ret as usize;
        }
        scause::Trap::Exception(const { Exception::StoreFault as usize })
        | scause::Trap::Exception(const { Exception::StorePageFault as usize }) => {
            todo!("终止进程");
        }
        scause::Trap::Exception(const { Exception::IllegalInstruction as usize }) => {
            todo!("终止进程");
        }
        scause::Trap::Interrupt(const { Interrupt::SupervisorTimer as usize }) => {
            set_next_timeout(TIMER_INTERVAL_USEC);
            TaskManager::cycle_to_next();
        }
        _ => {
            panic!("未处理的陷阱: {:?}, stval: {:#x}", scause, stval);
        }
    };
    trap_return();
}
```

#### set_user_trap_entry函数

该函数的主要作用是设置用户态陷阱入口相关的寄存器配置。通过修改`stvec`寄存器的值，将陷阱向量表的基地址设置为`TRAMPOLINE`地址，并指定陷阱模式为直接模式，以此确定在用户态发生陷阱情况时，系统会直接跳转到`TRAMPOLINE`地址指向的处理逻辑进行相应的中断或异常处理。

#### trap_return函数

用于实现从内核态返回到用户态的功能，在中断或异常处理完成后，通过一系列操作（如设置相关寄存器、执行特定汇编指令等），将程序执行流程切换回用户态，使得原本被中断的用户态程序可以继续正常执行下去。

**实现步骤：**

1. **重新设置用户态陷阱入口**：调用`set_user_trap_entry`函数，更新寄存器配置，确保正确处理未来的用户态陷阱。
2. **获取参数信息**：
   - 将陷阱上下文指针赋值给`trap_cx_ptr`，用于恢复程序执行现场。
   - 获取当前用户页表的token，存储到`user_satp`，用于管理用户态内存访问。
3. **计算返回地址**：通过特定逻辑计算返回到用户态的汇编函数`__restore_trap`的虚拟地址。
4. **执行返回用户态操作**：
   - 使用`asm!`宏嵌入汇编指令。
   - 执行`"fence.i"`指令，确保内存访问顺序一致性。
   - 跳转到`__restore_trap`汇编函数执行用户态恢复操作，传递必要的参数，并确保不会返回当前函数。

**源代码：**

```rust
#[unsafe(no_mangle)]
pub fn trap_return() ->! {
    set_user_trap_entry();
    let trap_cx_ptr = TRAP_CONTEXT;
    let user_satp = Processor::current_user_token().unwrap();
    let restore_va =
        extern_global!(__restore_trap) as usize - extern_global!(__save_trap) as usize + TRAMPOLINE;
    unsafe {
        asm!(
            "fence.i",
            "jr {restore_va}",
            restore_va = in(reg) restore_va,
            in("a0") trap_cx_ptr,
            in("a1") user_satp,
            options(noreturn)
        );
    }
}
```

#### trap_from_kernel函数
