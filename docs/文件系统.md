# 文件系统模块 - 总体介绍

## 简介

**文件系统**是操作系统的重要组成部分，负责**管理磁盘上的文件和目录**，**提供对持久化存储的访问**。通过文件系统，用户和程序可以方便地创建、读取、写入和删除文件，而无需关心底层的存储细节。

在本项目中，文件系统模块的设计基于 rCore 文件系统教程，结合实际需求实现了以下核心功能：
- **文件与目录的管理**：支持创建、读取、写入、删除文件，以及操作目录。
- **文件系统接口**：提供抽象的系统调用接口，屏蔽底层实现细节。
- **简易文件系统 (ros-fs)**：实现了一个高效且模块化的文件系统，包含块设备接口、块缓存管理以及磁盘布局。
- **内核中的文件系统支持**：通过集成 `ros-fs`，在内核中实现文件系统的初始化、文件描述符管理，以及文件读写功能。

本文件系统模块的目标是提供一个简单、高效、易于扩展的文件系统框架，同时支持在用户态和内核态的文件操作。

---

## 核心设计目标

1. **模块化设计**：  
   - 采用松耦合模块化设计，文件系统由多个层次构成，包括块设备接口层、块缓存层和磁盘布局层，各层次之间通过接口通信，便于扩展和维护。

2. **高效性**：  
   - 使用块缓存机制，减少磁盘 I/O，提高文件操作性能。

3. **可靠性**：  
   - 通过简单的磁盘布局设计和位图管理，保证文件系统的稳定性和数据一致性。

4. **灵活性**：  
   - 支持文件和目录操作，提供用户态和内核态的文件访问功能，满足不同场景的需求。

---

## 模块结构

文件系统模块的实现主要分为以下几个部分：

1. **块设备接口层**  
   - 提供统一的接口与底层存储设备交互，实现对磁盘块的读取与写入操作。
   - 接口定义在 `ros-fs/src/block_dev.rs` 中，支持多种存储设备的适配。

2. **块缓存层**  
   - 管理块的缓存，避免频繁的磁盘访问。通过 LRU 缓存策略，提升磁盘操作性能。
   - 实现在 `ros-fs/src/block_cache.rs` 中。

3. **磁盘布局层**  
   - 定义文件系统在磁盘上的布局，包括超级块、位图、索引节点和数据块等。
   - 实现在 `ros-fs/src` 中，核心文件包括 `super_block.rs`、`fs.rs` 等。

4. **文件系统接口层**  
   - 提供抽象的文件系统接口，包括文件打开、关闭、读写和目录操作等系统调用。
   - 接口定义在 `ros-fs/src/fs.rs` 中。

5. **内核集成层**  
   - 在内核中集成文件系统，实现文件描述符表和文件系统的初始化。
   - 实现在 `ros-fs/src/fs.rs` 中，支持应用程序对文件的访问。

## 文件和目录操作

### 创建文件

通过分配一个新的索引节点并更新父目录来创建文件：

```rust
pub fn create_file(&mut self, name: &str) -> Result<u32, &'static str> {
    // 检查文件是否已存在
    if self.find_entry(name).is_some() {
        return Err("File already exists");
    }
    
    // 分配新的索引节点
    let inode_id = self.alloc_inode().ok_or("Failed to allocate inode")?;

    // 创建目录项并添加到当前目录
    let new_entry = DirEntry {
        name: name.to_string(),
        inode_id,
    };
    self.add_entry(new_entry)?;

    Ok(inode_id)
}
```

### 删除文件

通过目录项查找文件并释放对应的索引节点和数据块：

```rust
pub fn delete_file(&mut self, name: &str) -> Result<(), &'static str> {
    // 查找文件对应的目录项
    let entry = self.find_entry(name).ok_or("File not found")?;

    // 释放索引节点和数据块
    self.dealloc_inode(entry.inode_id);

    // 从目录中删除目录项
    self.remove_entry(name)?;

    Ok(())
}
```

### 列举目录内容

返回目录下的所有文件和子目录名称：

```rust
pub fn list_entries(&self) -> Vec<String> {
    self.entries.iter().map(|entry| entry.name.clone()).collect()
}
```

## 文件描述符管理

文件描述符（File Descriptor，简称 FD）是文件系统与用户进程交互的重要机制。每个用户进程维护一个文件描述符表，用于管理其打开的文件。

### 数据结构

文件描述符表由以下数据结构表示：

```rust
pub struct FileDescriptorTable {
    table: HashMap<u32, FileDescriptor>, // 文件描述符映射到文件对象
    next_fd: u32,                        // 下一个可用的文件描述符编号
}
```

- **`table`**：存储文件描述符到文件对象的映射关系。
- **`next_fd`**：文件描述符表中的下一个可用文件描述符编号。

#### 文件描述符的定义

```rust
pub struct FileDescriptor {
    pub inode_id: u32,       // 对应文件的索引节点编号
    pub offset: usize,       // 文件当前读写位置
    pub flags: FileOpenFlags // 文件打开标志
}
```

- **`inode_id`**：文件对应的索引节点编号。
- **`offset`**：当前文件的读写位置。
- **`flags`**：文件打开标志，支持只读、只写、读写模式。

## 系统调用接口

以下是文件系统支持的主要系统调用及其实现：

### 打开文件

打开文件时分配一个文件描述符并初始化文件描述符表：

```rust
pub fn sys_open(&mut self, path: &str, flags: FileOpenFlags) -> Result<u32, &'static str> {
    // 查找文件对应的索引节点编号
    let inode_id = self.find_inode(path).ok_or("File not found")?;

    // 分配文件描述符
    let fd = self.alloc_fd()?;

    // 初始化文件描述符
    let file_descriptor = FileDescriptor {
        inode_id,
        offset: 0,
        flags,
    };
    self.table.insert(fd, file_descriptor);

    Ok(fd)
}
```

### 关闭文件

释放文件描述符表中的文件描述符：

```rust
pub fn sys_close(&mut self, fd: u32) -> Result<(), &'static str> {
    if self.table.remove(&fd).is_some() {
        Ok(())
    } else {
        Err("Invalid file descriptor")
    }
}
```

### 读文件

根据文件描述符读取文件数据：

```rust
pub fn sys_read(&mut self, fd: u32, buf: &mut [u8]) -> Result<usize, &'static str> {
    // 查找文件描述符
    let file_descriptor = self.table.get_mut(&fd).ok_or("Invalid file descriptor")?;

    // 获取对应的索引节点
    let inode = self.get_inode(file_descriptor.inode_id).ok_or("Inode not found")?;

    // 读取数据
    let read_size = inode.read_data(file_descriptor.offset, buf);

    // 更新文件偏移量
    file_descriptor.offset += read_size;

    Ok(read_size)
}
```

### 写文件

根据文件描述符写入文件数据：

```rust
pub fn sys_write(&mut self, fd: u32, buf: &[u8]) -> Result<usize, &'static str> {
    // 查找文件描述符
    let file_descriptor = self.table.get_mut(&fd).ok_or("Invalid file descriptor")?;

    // 获取对应的索引节点
    let inode = self.get_inode(file_descriptor.inode_id).ok_or("Inode not found")?;

    // 写入数据
    let written_size = inode.write_data(file_descriptor.offset, buf);

    // 更新文件偏移量
    file_descriptor.offset += written_size;

    Ok(written_size)
}
```

## 块缓存机制

### 背景

磁盘 I/O 是文件系统中最主要的性能瓶颈之一。通过在内存中缓存磁盘数据块，可以显著减少磁盘访问次数，从而提升文件操作性能。

### 实现

块缓存的实现基于 `BlockCache` 和 `BlockCacheManager` 两个核心组件。

#### 块缓存的结构

`BlockCache` 用于存储磁盘块的数据和元信息：

```rust
pub struct BlockCache {
    cache: [u8; BLOCK_SIZE],   // 缓存的数据
    block_id: usize,           // 缓存的磁盘块编号
    is_dirty: bool,            // 标识缓存是否被修改
    device: Arc<dyn BlockDevice>, // 块设备引用
}
```

- **`cache`**：缓存的磁盘块数据。
- **`block_id`**：对应的磁盘块编号，用于快速定位。
- **`is_dirty`**：标记缓存数据是否被修改，决定是否需要写回磁盘。
- **`device`**：与缓存关联的块设备。

#### 块缓存管理器

`BlockCacheManager` 管理所有缓存的磁盘块，使用 LRU 算法控制缓存的生命周期。

```rust
pub struct BlockCacheManager {
    caches: RwLock<LruCache<usize, Arc<Mutex<BlockCache>>>>, // LRU 缓存池
}
```

- **`caches`**：使用 `LruCache` 存储最近访问的缓存块，按 LRU 策略管理生命周期。

#### 核心方法

1. **访问缓存块**  
   如果缓存池中存在目标块，则直接返回；否则从磁盘加载该块并缓存：

   ```rust
   pub fn get_block_cache(&self, block_id: usize, device: Arc<dyn BlockDevice>) -> Arc<Mutex<BlockCache>> {
       let mut caches = self.caches.write().unwrap();
       if let Some(cache) = caches.get(&block_id) {
           Arc::clone(cache)
       } else {
           let cache = Arc::new(Mutex::new(BlockCache::new(block_id, device)));
           caches.put(block_id, Arc::clone(&cache));
           cache
       }
   }
   ```

2. **写回缓存块**  
   如果缓存块被修改（`is_dirty` 为真），将数据写回磁盘：

   ```rust
   pub fn sync_all(&self) {
       let caches = self.caches.write().unwrap();
       for cache in caches.iter() {
           cache.1.lock().unwrap().sync();
       }
   }
   ```

## 分级索引

### 背景

为了高效管理和访问大文件的数据块，文件系统采用分级索引结构，包括直接、间接和双重间接指针。

### 实现

索引节点的数据结构定义如下：

```rust
pub struct Inode {
    pub size: u32,                // 文件大小（字节）
    pub direct_blocks: [u32; 12], // 直接块指针（指向数据块）
    pub indirect_block: u32,      // 间接块指针（指向索引块）
    pub double_indirect_block: u32, // 双重间接块指针
}
```

#### 直接块指针

- 每个直接块指针指向一个数据块。
- 适用于小文件，存取速度快，无需额外的索引操作。

#### 间接块指针

- 间接块指针指向一个索引块，该索引块存储多个数据块的地址。
- 扩展了文件大小的支持范围，同时保持访问的高效性。

#### 双重间接块指针

- 双重间接块指针指向一个二级索引块。
- 适用于超大文件，通过两级索引扩展数据块的寻址范围。

#### 访问逻辑


## 延迟写回

### 背景

频繁的磁盘写操作会降低系统吞吐量。通过延迟写回策略，文件系统可以在一定程度上缓解这种问题。

### 实现

延迟写回依赖块缓存的 `is_dirty` 标志位。仅当缓存块被修改时，才将数据写回磁盘。

#### 核心逻辑

```rust
pub fn write_data(&mut self, offset: usize, buf: &[u8]) -> usize {
    let block_id = self.calc_block_id(offset);
    let block_cache = self.block_cache_manager.get_block_cache(block_id, self.device.clone());
    let mut cache = block_cache.lock().unwrap();
    cache.write(offset % BLOCK_SIZE, buf);
    cache.mark_dirty(); // 标记为脏数据
    buf.len()
}
```

- **`mark_dirty`**：标记缓存块为脏数据。
- **`sync_all`**：在文件系统关闭或同步操作时，将所有脏数据写回磁盘。

## 示例代码

以下示例展示了文件系统的性能优化机制如何提升文件操作效率：

```rust
fn main() {
    let device = Arc::new(MemBlockDevice::new(1000));
    let cache_manager = BlockCacheManager::new();

    // 写入数据
    let data = b"Optimized file system performance";
    let block_cache = cache_manager.get_block_cache(0, device.clone());
    {
        let mut cache = block_cache.lock().unwrap();
        cache.write(0, data);
    }

    // 同步缓存
    cache_manager.sync_all();
    println!("Data written and synchronized to disk.");
}
```
